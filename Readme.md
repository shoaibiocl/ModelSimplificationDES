## Data Generation & Simulation Testbeds

This repository utilises discrete-event simulation (DES) models built with the `salabim` library to generate empirical data. 
These datasets capture how changes in server utilisation impact event trace counts and wall-clock execution times. 

## Description of each file is detailed below.

### 1. 2-Stage Tandem Queue Number of Instructions Generator (`generate_instructions_data.py`)
This script is used for generating number of instructions data for both parent and simplified models across different utilisation values.
* **Disciplines:** $M/M/1, M/G/1,$ and $G/G/1$
* **Systems:** 2-stage (parent), 1-stage, and simplified (1-stage+ rv)

### 2. 2-Stage Tandem Queue Runtime Generator (`generate_runtime_data.py`)
This script is used for generating empirical execution runtimes data for both parent and simplified models across different utilisation values.
* **Disciplines:** $M/M/1, M/G/1,$ and $G/G/1$
* **Systems:** 2-stage (parent), 1-stage, and simplified (1-stage+ rv)
* ** Also used for validation experiment 1.


### 3. 3-Stage System: Validation Experiment 2 (`generate_data_3stage_branched_parent.py`)
This script is used for generating execution runtimes data for both parent and simplified models across different utilisation values for validation experiments 2.
* **System:** 3-stage tandem queuing system with two parallel subsystems in the third stage.



### 4. Sampling Sensitivity (`test-sampling-sensitivity.py`)
Before using the generated event trace logs to train predictive frameworks, this script runs a sensitivity experiment. It verifies whether changing the scale of entity sampling significantly affects the: **Instructions per Arrival**.

* **Statistical Methodology:** Executes a one-way ANOVA across different sampling values to test the null hypothesis ($H_0$) that the sample size does not affected the recorded instructions across group means.
  * **95% Confidence Interval (CI) Estimation:** Computes the standard error of the mean (SEM) for each sample bracket and applies a Student’s t-distribution critical value to map precise interval bounds:
  $$\text{CI} = \bar{x} \pm \left(t_{\alpha/2, \, df} \times \text{SEM}\right)$$
* **Input Data:** Reads empirical tracking categories from `data/raw/ModelSimplification-NI-Sensitivity.xlsx` (Sheet 2), where each column represents a different sample size threshold.
* **Visual Artifact:** Automates the creation of a high-contrast validation plot detailing the variance, mean markers, and overlapping interval whiskers for each group.

### 5. AnyLogic Trace Log Parser (`generate-instructions-data-AnyLogic.py`)
To parse event trace logs generated by **AnyLogic** simulation environments. 
* **Total Trace Count** for every agent that traversed the system.
* **Input Data:** Expects AnyLogic tarce data at `AnylogicLogData.xlsx`.
* **Visual Artifact:** Generates a population frequency histogram mapping the density profile of agent call frequencies, visualising the distribution of system interactions.
* **Output Asset:** Writes a summary (`Agent Counts` and `Frequency Distribution`) to and Excel spreadheet.

### 6. Validation of LoS Random Variable ('validation-klDivergence.py`)
This script is used to perform KL-Divergence test to measure the distance between the length of stay data sets generated by parent and simplified models.

### 7. Non-Parametric Input Modelling ('los-rv-2stage.py`)
This script was utilised for non-parametric input data modeling. It fits an optimized Kernel Density Estimation (KDE) model to empirical Length of Stay 
(LOS) data. This is deployed as an alternative input modeling strategy when standard parametric distributions (e.g., Exponential, Normal, Gamma) fail to 
provide an acceptable statistical goodness-of-fit.

### 8. Non-Stationary Systems: Validation Experiment 3 ('generate-runtime-data-non-stationary-system.py`)
This script was used to model the 2 stage parent M(s)/M(s)/1 system with non-stationary arrival and service patters as a part of validation experiment 3.
